# MIS-002 Schema v2 Replan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` to implement this plan task-by-task. Each task follows TDD, receives specification review and quality review, and ends in a focused commit. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reconcile canonical M2 coverage, accept `CAP-EXECUTION`, create and exact-hash approve a two-Milestone `MIS-002` schema-v2 Replan, mechanically recalculate R0–R4, and preserve an explicit Operator-only M2-unblock gate without implementing the M2 Worker.

**Architecture:** Product doctrine remains in the accepted Product Blueprint, ADRs, roadmap and MCRM. Capability requirements and readiness remain in `CAP-EXECUTION/TRACEABILITY.json`; the approved Mission contract remains append-only SQLite state materialized through the existing planning service. A stable `SEC-E1` definition is hash-bound by the contract, while every future Attempt separately records its run-specific effective compiled-policy hash.

**Tech Stack:** Node.js 24.18+, TypeScript 5.9, `node:test`, SQLite through `node:sqlite`, deterministic Markdown/JSON generators, Pi planning skill, Lavish, GitHub Actions and Ubuntu WSL2.

## Global Constraints

- Execute from a Linux-owned checkout in canonical Ubuntu WSL2.
- Historical `MIS-002` revision 3 remains byte-for-byte immutable:
  - blob: `6b79117fe66cd5c9c8142099828812f470ce20de`;
  - content hash: `sha256:f95ffded37af764e5f76775ec6bbdda69d5638246609451ce37bf524908cf8c1`.
- Never edit `.mnfs/missions/MIS-002/plan.json`, planning SQLite rows, rendered HTML or Lavish state manually.
- New content uses `schemaVersion: 2` and is saved against the exact current approved hash.
- Mission, Milestone and Feature criteria are separately decidable; child success never auto-accepts a parent.
- M2 remains one fixed deterministic task, one Write Track, one current Attempt and one Pi Worker Run at a time.
- `SEC-E1` denies network and credentials, limits effects to X0/X1 and fails closed.
- The AS-02 effective policy hash is evidence for its accepted run, not the reusable Mission policy-definition hash.
- Worker completion is never Claim acceptance.
- No deciding criterion depends on Herdr, Observational Memory, `pi-link`, remote execution or an external observability backend.
- No Worker implementation, dispatch, Plan approval, PR merge or M2 unblock is inferred from CI, prose or earlier approvals.
- Operator gates require the exact literal tokens specified in Tasks 5, 7 and 9.
