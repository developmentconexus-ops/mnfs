| D-010 | 2026-08-07 | Adopt `DOC-MNFS-DEVELOPMENT-GOVERNANCE-METHOD` as the development decision policy for MNFS. Architecture discovery must search the best-supported global solution rather than optimize only inside prior Blueprint/ADR/Roadmap/Mission assumptions. Authority freezes bounded execution, not inquiry. Development is separated into Discovery, Decision and Execution loops; prior Decisions remain authoritative until explicitly superseded, but may be challenged by stronger Evidence. Replan may be triggered by necessity **or opportunity** when a materially better architecture outweighs migration/decision cost. Sunk cost is not technical justification. Proprietary product runtimes are architectural references by default and require explicit sovereignty/exit analysis before foundational adoption. `MIS-002/M02` microdesign is paused as the next gate while a global Architecture Realization Review reassesses planning semantics, agent/session runtime, execution workspace and implementation sourcing. M02 production implementation and Worker dispatch remain prohibited. | Operator | — |
| D-011 | 2026-08-07 | Approve Architecture Realization Review D1 — Planning and Validation semantics. Preserve the Mission/Milestone/Feature hierarchy and Acceptance Criterion model, but make **correctness definition precede implementation decomposition**. The approved semantic direction is: Operator Intent → Investigation → Mission correctness definition → adversarial correctness review → validation baseline → Milestone/Feature decomposition → child criteria and coverage → architecture/planning → approval. The Mission-level Acceptance Criteria plus their Verification Plans serve the **Validation Contract role**; do not add a duplicate authoritative `ValidationContract` entity merely to mirror another product. Add explicit upward contribution lineage (`CONTRIBUTES_TO` or equivalent) so child criteria/features can be traced to parent outcomes. Validators judge and produce Findings by default; they do not implement corrections. Findings route to a new Attempt/Correction when existing scope is wrong, a new Feature when a missing implementation unit is discovered, or Decision/Replan when the contract/intent is wrong. Planning rigor remains proportional to risk. This decision approves semantics only; schema, Blueprint, MCRM and contract migrations are deferred to the Architecture Realization Review reconciliation package after D2–D4. | Operator | — |
| D-012 | 2026-08-07 | Approve Architecture Realization Review D2 — Agent Runtime and Session/Coordination direction. MNFS owns Role, ActorRun, Attempt, Authority, Current Authority Snapshot, Claim/Evidence/Verdict and durable recovery semantics; coding-agent loops, model/provider mechanics, runtime sessions and live transport are replaceable substrates. Runtime Session identity is observational and MUST NOT become Mission/ActorRun authority; domain recovery MUST work without runtime-session resume. Do not build a custom MNFS agent loop while credible open substrates exist. Evaluate ACP as the preferred open interoperability boundary through a **comparative Architecture Spike**, not as a preselected dependency. The spike must compare at least two real runtime paths and include Pi as the incumbent with accepted AS-02 Evidence; OpenCode/ACP is the strongest current challenger, and a second ACP implementation such as Pi-ACP or Goose is required before treating protocol interoperability as proved. The spike must compare deterministic resource inventory, exact cwd/environment, E1 composition, auth/provider compatibility, cancellation, event/final-turn semantics, bounded output, process death, fresh MNFS recovery without transcript, structured results, version pinning and operational complexity. If ACP fails to reduce total complexity without weakening authority/security, use a concrete runtime-specific adapter instead. Mastra AgentController/Signals remain REFERENCE/DEFER until a named long-lived session/control consumer exists; OpenHands remains REFERENCE/DEFER for broader remote/server execution. This decision approves the boundary and spike direction only; no runtime is selected and no production dispatch is authorized. | Operator | — |
