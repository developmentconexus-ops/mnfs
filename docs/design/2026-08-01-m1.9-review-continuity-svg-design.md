# M1.9 — Lavish Review Continuity and Static SVG Design

**Date:** 2026-08-01  
**Status:** approved by the operator  
**Scope:** finish M1 by fixing two defects discovered in the real Pi + Lavish pilot

## Problem 1 — a new Lavish session opens for every revision

Lavish keys a review session by the canonical HTML file path. MNFS currently renders each revision to a different path:

```text
artifacts/plans/<mission-id>/rev-0001.html
artifacts/plans/<mission-id>/rev-0002.html
```

When Pi saves a newer revision and runs `plan open`, Lavish sees a different path and creates a different browser session. The operator loses the conversation history and must approve again.

## Decision 1 — stable review path plus immutable snapshots

Each rendered revision produces both:

```text
artifacts/plans/<mission-id>/review.html
artifacts/plans/<mission-id>/rev-<NNNN>.html
```

- `review.html` is the stable Lavish session identity and is atomically replaced on every render.
- `rev-<NNNN>.html` is an immutable audit snapshot for that revision.
- `plan open` and `plan poll` always use `review.html`.
- The Pi skill runs `plan open` only for the first browser opening. Later revisions run `plan render` and continue polling the stable path, letting Lavish live reload the same tab and preserve conversation state.

`RenderPlanResult.htmlPath` remains the stable review path for compatibility and gains `snapshotPath` for evidence.

## Problem 2 — dependency graph is raw Mermaid source

The renderer writes `<pre class="mermaid">...</pre>` but deliberately loads no Mermaid runtime. A normal browser therefore displays text instead of a graph.

## Decision 2 — deterministic inline SVG without a new dependency

MNFS will generate a static inline SVG directly from the validated milestone and feature dependency DAG.

The layout is deliberately small and deterministic:

- nodes are ordered by validated plan order;
- topological depth determines the column;
- plan order within each depth determines the row;
- milestone and feature nodes have distinct classes;
- every edge has a deterministic `data-edge="SOURCE->TARGET"` marker;
- node IDs and titles are included as escaped SVG text;
- full node titles remain available through `<title>`;
- no Mermaid library, CDN, browser runtime, Graphviz process or random measurement is introduced.

The graph panel is omitted when there are no dependency edges.

## Boundaries

- SQLite and the structured mission plan remain authoritative.
- HTML and SVG remain deterministic projections.
- The fix does not change plan hashes or approved contracts.
- No workers, Treehouse adapter, Herdr adapter or M2 implementation is added.
- Existing approved `MIS-002` remains valid; only the rendered review artifact changes.

## Failure handling

- Atomic publication failures keep using `PLAN_MATERIALIZATION_FAILED`.
- A missing stable review file is repaired by `plan render` or `plan open`.
- Lavish is never asked to infer session continuity from a revision-specific path.

## Acceptance

### Automated

- two revisions have the same `htmlPath` and different `snapshotPath` values;
- both files contain the current revision bytes after render;
- `plan poll` uses `review.html`;
- skill instructions open once, then render and poll after revisions;
- HTML contains inline `<svg class="dependency-graph">` and no raw Mermaid block;
- every dependency node and edge is represented;
- text is escaped and output is byte-identical for the same revision;
- no external script, CDN or Mermaid dependency is introduced.

### Real browser retest

- the existing Lavish tab reloads after a revised plan is saved;
- conversation history remains visible;
- the dependency graph appears as SVG;
- exact-hash approval succeeds without opening another review session.
