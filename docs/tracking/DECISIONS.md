| D-011 | 2026-08-07 | Approve Architecture Realization Review D1 — Planning and Validation semantics. | D-013 | 2026-08-07 | Approve Architecture Realization Review D3 — Execution Environment architecture. Preserve the separation of Domain Authority, Tool Capability, Process Sandbox, Execution Environment, Credential, Network/Egress, External Effect and Evidence/Reconcile planes, but supersede the ordinal `E0 → E4` technology/locality ladder as the semantic model. Execution Environments are defined by independent properties such as agent placement (`CONTROL_SIDE` or `IN_ENVIRONMENT`), compute location, isolation boundary, mutable-workspace model, persistence/snapshot/fork capability, network posture, credential delivery, recovery capability and a provider-neutral Git result boundary. `WriteTrack` semantically owns an isolated mutable workspace; it is not inherently a Git worktree. Git base/result identity remains canonical (`baseCommitSha` + `resultTreeSha`, optionally a result commit); worktree paths, COW deltas, QCOW2 disks, VM snapshots and remote volumes are replaceable execution artifacts, never acceptance authority. Prefer split-plane/control-side agent placement when a runtime can be strictly reduced to MNFS-brokered capabilities so model/provider credentials stay outside untrusted execution; require whole-agent/in-environment placement when that reduction cannot be proved, with brokered credentials/inference preferred over raw secrets. Keep implementation concrete and YAGNI: property-independent semantics do not authorize generic provider factories without a second real consumer. Before selecting local substrates, run a host-capability probe, then comparative local process-envelope and microVM-envelope spikes. Anthropic Sandbox Runtime is the process incumbent; `nono` is the leading current process challenger, with Sandlock conditional on host-kernel support. BoxLite and `smol-machines/smolvm` are the leading microVM challengers. VFS/AgentFS workspace selection is deferred until the chosen execution envelope demonstrates whether an additional COW substrate is still needed. OpenShell and OpenSandbox remain strong whole-agent/control-plane references; E2B, Mitos, Sandbox0 and Kubernetes Agent Sandbox remain strong future remote/parallel candidates. This decision approves semantics and spike direction only; no Execution Environment substrate is selected and no production Worker dispatch is authorized. | Operator | — |
| D-014 | 2026-08-07 | Approve Architecture Realization Review D4 — Implementation Sourcing Strategy. MNFS shall be realized as a **Thin Sovereign Semantic Kernel + Selective Open Substrates**: MNFS owns differentiated semantics and authority (work definition, planning/validation, Role/ActorRun/Attempt, Claim/Evidence/Receipt/Finding/Verdict, Recovery/Reconcile, Engineering Governance, Credential/Effect Governance, Evaluation/Calibration and Operator control meaning), while non-differentiated machinery is presumed `ADOPT`/`ADAPT` when a replaceable open substrate eliminates a meaningful machinery class without becoming a second authority. Formalize `OWN / ADOPT / ADAPT / SPIKE / REFERENCE / DEFER / REJECT` as capability-realization vocabulary. Every material sourcing decision must pass semantic-ownership, authority-inversion, mechanical-leverage, replaceability/exit, proofability, sovereignty/license and named-consumer tests. Prefer the lowest sufficient upstream layer, one primary substrate per concern, and reject a dependency that merely adds integration surface without eliminating meaningful machinery. Small local implementations may beat dependencies when simpler. Foundational dependencies require pinned provenance, supported public boundary, conformance proof, upgrade policy and Removal Conditions; proprietary foundational runtimes are `REFERENCE` by default unless an explicit Operator Decision accepts the sovereignty trade-off. The tool registry is a projection of capability-realization decisions, not the source of architectural truth. Do not build custom agent loops, browsers, hypervisors, VCS/database engines, generic workflow infrastructure or other commodity machinery by default while credible substrates exist. This decision approves sourcing policy only; concrete Agent Runtime and Execution Environment selections remain subject to the approved D2/D3 spikes and no production Worker dispatch is authorized. | Operator | — |
